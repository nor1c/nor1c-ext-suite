# Plan: Ad Link Bypass Feature

## Goal
Add a content script feature that intercepts ad/redirect links on quicklink/download sites, bypassing the intermediate ad page and navigating directly to the real destination URL.

## Problem
On sites like quicklink pages, download hubs, etc., clicking a link:
1. Opens a NEW TAB with an ad/redirect URL (e.g. adf.ly, linkvertise, ouo.io)
2. The real destination is hidden behind a timer, captcha, or redirect chain
3. User must wait or manually extract the real link

## Approach: `content/ad-link-bypass.js` content script

### How ad redirects work (patterns to intercept)
1. **JS `window.open()`** — click handler calls `window.open(adUrl)` then later `window.open(realUrl)` or navigates
2. **`target="_blank"` + href swap** — anchor has `href=adUrl` with `target="_blank"`, real URL in `data-*` attribute
3. **`onclick` handler** — `<a onclick="goToLink('realUrl')">` with `href="#"` or `href=adUrl`
4. **Intermediate redirect page** — first click opens `adserver.com/redirect?dest=REAL_URL`, which 302s to real URL after loading ads

### Interception strategy

**Layer 1: Hook `window.open()`**
- Override `window.open` in page context (via injected script, like watcher.js pattern)
- Check if URL matches known ad/redirect patterns (adf.ly, linkvertise, ouo.io, etc.)
- If match → cancel the ad tab, extract the real `dest`/`url` parameter, navigate current tab or open direct

**Layer 2: Intercept anchor clicks**
- Listen for click events (capture phase) on `<a>` elements
- If `target="_blank"` AND href matches ad patterns → prevent default, extract real URL
- Check common data attributes: `data-url`, `data-href`, `data-link`, `data-destination`

**Layer 3: Known redirect URL extraction**
- For common link shortener domains (adf.ly, linkvertise, ouo.io, etc.), extract the `dest`/`url`/`go` query param from the URL
- Strip tracking params (`utm_*`, `ref`, `aff`, etc.)
- Navigate directly to destination

**Layer 4: Debounce + fallback**
- If URL can't be extracted, let original behavior proceed (don't break legitimate links)
- Short debounce to avoid double-navigation

### Implementation details

**`ad-link-bypass.js` structure:**
```js
(function() {
  let enabled = false;
  const AD_DOMAINS = [
    'adf.ly', 'linkvertise.com', 'ouo.io', 'ouo.press',
    'shrinke.me', 'sh.st', 'bc.vc', 'cuturl.cc',
    'bit.ly' // only redirect hops, not direct bit.ly links
  ];
  const AD_URL_PATTERNS = [
    /[?&](dest|url|go|link|redirect|destination)=/i,
    /\/(go|redirect|out|away|visit)\//i
  ];

  // Check if URL is an ad/redirect link
  function isAdRedirect(url) { ... }

  // Extract real destination from ad URL params
  function extractRealUrl(adUrl) { ... }

  // Hook window.open via page-context injection
  // Intercept click events on anchors
  // ...

  // Listen for toggle-changed messages
  chrome.runtime.onMessage.addListener((msg) => {
    if (msg.type === 'toggle-changed' && msg.key === 'adLinkBypass') {
      enabled = msg.value;
    }
  });

  // Initial state load
  chrome.storage.sync.get(['adLinkBypass'], (r) => {
    enabled = !!r.adLinkBypass;
  });
})();
```

**Page-context injection (for window.open hook):**
Content scripts run in isolated world — can't hook `window.open` directly. Need to inject a script tag into the page's JS context, same pattern as `video-downloader-inject.js` / `watcher.js`.

**Key safety:**
- Only intercept when `enabled === true`
- Whitelist approach: only act on URLs matching known ad domains OR known redirect URL patterns
- Never block navigation to unknown URLs (don't break normal browsing)
- Show a brief notification bar or console log when bypassing (optional, for transparency)

### Tests / Validation
1. Toggle ON → visit a site with adf.ly/ouo.io redirects → clicking should skip ad page, navigate directly
2. Toggle OFF → same site → normal behavior (ad page opens)
3. Test on non-ad sites → no behavior change, links work normally
4. Test `window.open` hooks don't break popup/modal windows on normal sites
5. Test edge: links that use both `target="_blank"` AND `onclick` handlers

### Risks / Tradeoffs
- **False positives**: Legitimate redirect URLs (OAuth, SSO) could match patterns → mitigated by domain whitelist approach
- **Site breakage**: Some sites detect blocked popups and show error messages → fallback lets original behavior proceed
- **Circumvention**: Sites may change redirect patterns → AD_DOMAINS list needs maintenance (could be user-editable later)
- **CSP restrictions**: Some sites block injected scripts → window.open hook won't work, falls back to click interception only

### Open Questions
- Should bypassed URLs open in same tab or new tab? (suggest: same tab by default, modifier key for new tab)
- Should we add a small notification/banner when a bypass happens? (suggest: optional, off by default)
- User-editable ad domain list via popup settings? (suggest: v2, not in initial implementation)
