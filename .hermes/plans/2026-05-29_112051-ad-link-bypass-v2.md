# Plan: Rewrite Ad Link Bypass — Heuristic Approach

## Problem

Current approach fails because:
1. `<a>` has no `href` — click handler bails at line 116 (`if (!anchor || !anchor.href) return`)
2. Hardcoded `AD_HOSTS` list can't cover all ad networks (crn77.com not in list, thousands exist)
3. Ad URL (`https://crn77.com/4/9172134`) contains NO destination param — real URL is elsewhere on page
4. Real destination URL lives on the PAGE (hidden `<a>`, JS variable, `data-*` attribute), not in the ad link

## New Approach

Instead of domain list + URL param extraction, use **heuristic ad detection** + **page scanning for real URLs**.

### Step 1: Rewrite `window.open` hook (page-context script)

The hook intercepts ALL `window.open()` calls. For each call:

```
1. Check if URL looks like an ad tracker:
   - Short path with numeric ID: /4/9172134, /5/12345
   - Known ad patterns: /ad/, /click/, /go/, /out/
   - URL is NOT the same domain as current page (cross-origin popup)
   
2. If ad-like → BLOCK the window.open (don't let new tab open)
   → Call searchPageForRealUrl() to find destination on current page
   → If found → navigate current tab to real URL
   → If NOT found → still blocked (user can disable toggle)

3. If NOT ad-like → call original window.open() (let it through)
```

**Key difference from old approach**: blocking happens IN the page-context hook synchronously, before the new tab opens. No async gap.

### Step 2: Rewrite click handler for `<a>` elements

New logic:
```
1. Walk up from click target to find nearest <a>
2. If <a> has href → check if ad-like (heuristic) → block + scan page
3. If <a> has onclick with window.open → ALSO check those URLs (extract from onclick attribute string)
4. If <a> has no href but has onclick → extract URL from onclick, check ad-like, block + scan page
```

### Step 3: Ad URL heuristic (replaces domain list)

```js
function isLikelyAdUrl(url, currentHostname) {
  // Must be cross-origin (ads always redirect to different domain)
  if (hostname === currentHostname) return false;
  
  // Short numeric path pattern: /4/9172134, /5/123
  if (/^\/\d+\/\d+\/?$/.test(path)) return true;
  
  // Known ad path patterns
  if (/\/(ad[s]?|click|go|out|away|visit|redirect|track|link)\//i.test(path)) return true;
  
  // Known ad query params (tracking IDs)
  if (/[?&](aff|affiliate|ref|campaign|click_id|track)/i.test(url)) return true;
  
  return false;
}
```

### Step 4: Page scanning for real destination URL

When an ad is blocked, scan the current page for the real destination:

```js
function findRealDestination() {
  // 1. Scan all <a> tags — find ones with href to DIFFERENT domain than current page
  //    that are NOT the ad URL itself
  //    Prefer: visible links, links near the click target, links with download/continue text
  
  // 2. Check page JS globals: window.destinationUrl, window.realLink, etc.
  
  // 3. Check hidden inputs/data attributes for URLs
  
  // 4. Check inline scripts for URL assignments
}
```

### Step 5: Safety valve — URL confirmation

Since this is aggressive (blocks ALL cross-origin short-path popups):
- Add `crn77.com` and common ad networks to a SMALL known list (not the primary mechanism, just a fast path)
- When blocking, log to console so user can debug: `[Nor1c Suite] Blocked ad popup: crn77.com/4/9172134`
- Toggle is OFF by default? Or ON with easy disable.
